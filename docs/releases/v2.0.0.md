# Gmail Hide Ads v2.0.0

## A Brainfuck policy core, compiled ahead of time

This release moves every decision into Brainfuck, without changing what the module removes.

### Changed

- The decision policy is now two Brainfuck programs in `libgmailbf.so` (`brainfuck/src/row.bf`, `scope.bf`), compiled ahead of time to C and then to native code with the NDK. There is no interpreter in the APK.
  - `row`: whether a view class, or any of its superclasses, is named `com.google.android.gm.ads.…AdTeaserItemView`.
  - `scope`: whether the package is Gmail and the process is the main one, or one the framework did not name.
- Hooks, the superclass walk, the per-class cache and row collapsing stay in Java. The first view of each class makes one `@FastNative` call with its class names as one small code per character; every later view of that class is answered from the cache.
- Fails open on any policy failure: a missing library or ABI mismatch installs nothing, and an oversized, malformed or budget-exhausted request keeps the row.
- New adaptive vector launcher icon — a struck-through, broken shield over the Gmail M — with a themed (monochrome) layer.
- The collapsed-row log line now carries the policy counters.
- CI runs the Brainfuck toolchain tests and the parity suite before building, checks that the native library ships for every ABI, and publishes these notes from `docs/releases/`.
- The README follows the ThreadsHideAds layout; the design is documented in `docs/BRAINFUCK_ARCHITECTURE.md` and each program has a normative specification in `docs/policy/`.

### Also in this release

- The application id is now `io.github.mrxsin.gmailhideads`. Android treats this as a new app: uninstall 1.0.0 (`my.MrxSiN.gmailhideads`) and enable the new module.
- The launcher theme no longer needs API 29, fixing two `NewApi` lint errors on the API 26 minimum.
- Release signing fails in seconds with a named cause when a keystore secret is wrong, and tolerates CR characters in the base64 keystore.

### Verified

- Parity with the 1.0.0 Java policy, kept as a frozen test oracle: 634 229 old-versus-new comparisons per run on the JVM and on a Pixel 8 Pro (arm64, Android 17), including every character from U+0000 to U+FFFF in nine contexts, plus randomized, malformed-frame, truncation and concurrency tests.
- On the Pixel 8 Pro (release build) a policy request takes about 1 µs, against 0.2 µs for the two string comparisons it replaces; it runs once per view class, and the cached `addView` path is unchanged at 0.12 µs.

2.0.0 has not yet been run inside Gmail under Vector; the 1.0.0 on-device validation against Gmail `2026.08.17.974752392.Release` is in the README. LSPatch, 32-bit and x86 devices were not run for this release.

### Updating

Uninstall 1.0.0 if it is installed, install the v2.0.0 APK, enable **Gmail Hide Ads** in your framework manager, then force-stop and reopen Gmail once. Confirm the framework log reports `policyCore=brainfuck-aot abi=1.0` followed by `Layer installed: ad-teaser`.
